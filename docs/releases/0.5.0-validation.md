# 0.5.0 validation — 20 October 2026

The application changes are validated. The owner subsequently explicitly
authorized merge, publication, deployment, and live agent-browser validation.
The assessment below records the residual upstream findings rather than
suppressing them. Publication and deployment results will be recorded on
[PR #6](https://github.com/cotdp/scraper-mcp/pull/6) and the GitHub release.

## Application and package checks

- 387 tests passed, with 79% source coverage. The single warning is Starlette's
  deprecation of its httpx-based TestClient interface.
- Ruff lint/format, strict mypy across 41 source/script files, actionlint, and
  the existing Biome checks passed. The locked environment resolves with uv 0.13.3.
- The hashed, all-extras dependency export passes strict `pip-audit` with no
  known vulnerabilities and no advisory exclusions.
- Wheel and sdist builds pass. The wheel contains the dashboard and eight
  explicit transitive security floors; DiskCache is absent.
- Independent review findings were fixed, including TLS cache-policy separation
  and security constraints being absent from wheel metadata.
- Native browser checks passed Basic authentication, stats/config retrieval,
  TLS defaults, masked proxy round-trips, citation/attribute escaping, and
  desktop/mobile navigation. The 390px overflow found during testing was fixed.
- A live direct Perplexity Sonar request passed with eight total tokens.
  OpenRouter registration and behavior are covered by automated tests, but no
  injected OpenRouter credential was available for a live call.

The offline production-image smoke exercises a real Streamable HTTP MCP
handshake, tool discovery, static scraping, Chromium rendering, cache writes,
admin authentication, masked configuration, and TLS defaults. It also verifies
that the process is unprivileged and cannot write the application or environment
directories. It passed after the final Docker changes.

### Deployment assessment after explicit owner authorization

A fresh scan of the candidate reproduces the findings above. The currently
deployed image, `sha256:8df3a95fd3f4653cc40a2936bcb2e22c99c30b9e83d3685e7da1c25ee37272c6`,
has 10 critical / 148 high OS findings, 2 critical / 9 high Python findings,
and a medium uv finding. There are 231 scanner-listed OS fixes in that old
image; the candidate applies the available fixes.

[Debian's CVE-2026-6653 assessment](https://security-tracker.debian.org/tracker/CVE-2026-6653)
describes a crafted-XML denial of service and classifies trixie as a minor issue
with no DSA planned. This contextualizes the scanner's critical rating without
changing its result. The candidate has no CUPS daemon, systemd-homed service,
or Python libxml2 bindings; several high findings concern those components.
The application launches Chromium headlessly rather than running the installed
Xvfb. These observations do not prove every remaining advisory unreachable.

The latest stable lxml is already locked at 6.1.3. Its bundled libxml2 is 2.14.6:
package-level audit success does not cover every native-library advisory.
For example, [CVE-2026-86138](https://security-tracker.debian.org/tracker/CVE-2026-86138)
is fixed upstream in libxml2 2.15.4. The application uses the HTML parser with
`huge_tree=False` and does not request DTD validation, XInclude, or XPointer;
exploitability of the remaining native findings has not been established.
The distribution's lxml minimum is raised to 6.1.3 to include its separate
[parameter-entity parsing fix](https://pypi.org/project/lxml/6.1.3/).

The release decision is to deploy the measured hardening under the owner's
explicit directive, preserving trusted-network bindings, the memory limit,
non-root execution, and the previous container for rollback. No security check
is bypassed, no advisory is dismissed, and no scanner exclusion is added.
Continue tracking upstream OS and native-library fixes and rescan the exact
published image. A clean package audit must not be described as a clean image.

Reproduce after rebuilding `scraper-mcp:0.5.0-rc`:

```bash
docker run --rm --network none -i scraper-mcp:0.5.0-rc python - < scripts/smoke_image.py
trivy image --image-src docker --scanners vuln --ignorefile /dev/null \
  --format json --output image-audit.json scraper-mcp:0.5.0-rc
```

## GitHub and publication handoff

Dependabot fixes are enabled. Main requires a PR, resolved conversations, and
up-to-date `quality` and `Analyze (python)` checks from GitHub Actions, including
for administrators. Force pushes and branch deletion are disabled.

The initial hosted quality and CodeQL checks passed; final check results are
attached to [PR #6](https://github.com/cotdp/scraper-mcp/pull/6). No open secret
alerts or CodeQL findings were returned for the audited PR. The 35 existing
Dependabot alerts remain on the default branch until the dependency changes are
merged and GitHub re-evaluates them.

Docker Hub secret names are configured; registry credential validity and GHCR
package inventory were not verified. The current CLI token lacks
`read:packages`. Local container execution covered amd64; the release workflow
must still verify publication for both amd64 and arm64 after owner merge.

The original dirty checkout was preserved. SearXNG remains a separate feature
follow-up with acceptance criteria in the task plan. Follow [RELEASE.md](../../RELEASE.md)
for the authorized publication; do not tag the preparation branch.
